## Background
Previously, we created a big matrix $A_{aug}$ ($A_{aug}$ contains the pde data, boundary conditions, regularization) and implemented sketch-and-project algorithms on it so we do not have to create a big matrix $A^TA$. That did not solve the problem of the underlying $A$ matrix being big in the first place, which causes OOM issues. Hence, we want to avoid creating the matrix $A_{aug}$ in the first place to cut down on memory usage. We can take a **sample first approach by building a mini-batched subset of random coordinates first**, and evaluating the network only on those points to generate $A_B$ and $b_B$ on the fly. $A_B$ contains the list of features and $b_B$ is the ground truth vector that is fetched from the dataset.

## Tackling a larger A matrix
**Sampling to create mini-batches**
When the $A_{aug}$ matrix becomes large, the number of internal PDE points can vastly outnumber the boundary conditions as grid density increases. Purely uniform random sampling may therefore cause the solver to statistically under-represent the boundary constraints.

To address this, we try 2 methods.
1. Uniform Random Sampling with replacement
2. Stratified Sampling with replacement
    Boundary conditions can be sampled with higher weighting.

    *Example Batch Composition*

    | Component                    | Batch Size | Sampling Mechanic |
    |------------------------------|------------|-------------------|
    | PDE Batch                    | 350 rows   | Random with replacement |
    | Neumann BC Batch             | 50 rows    | Random with replacement (Oversampling) |
    | Periodic BC Batch            | 50 rows    | Random with replacement (Oversampling) |
    | $L_2$ Regularization Block   | 50 rows    | Random sample from static identity matrix |
